**Vibration Models** in the left menu holds every vibration model of the tenant. One model is bound to one device
or asset profile: it reads the waveform telemetry of every machine under that profile and turns each sample it
scans into stored results, from overall metrics and spectra to an ISO severity zone and the shaft or bearing
pattern that fits best.

## How it fits together

1. The [Vibration Models list](#vibration-models-list) holds every model. Opening one leads to its
   [model page](#model-page).
2. The **Overview**, **Monitoring**, and **Analyzer** tabs read the results the model has stored. They show
   nothing for a period that was never scanned.
3. The [actions](#actions) scan samples into stored results: the newest ones, or a period you choose. Scheduled
   scanning runs the same scan on its own.
4. Every scan runs as an execution of the model's task, listed on the [Tasks tab](#tasks-tab).
5. The **Properties** tab holds the configuration every scan follows.

Each row in the table shows:

| Column | Description |
|--------|-------------|
| **Name** | Model name and the profile it reads |
| **Created** | When the model was created |
| **Telemetry key** | The key that holds the waveform, with the axis count and the points per sample |
| **Alarms** | Open alarms raised by this model's rules |
| **Monitoring** | Whether scheduled scanning is enabled |
| **Saved as telemetry** | Whether each scan writes the selected metrics back to ThingsBoard |
| **Items** | Machines scanned, out of the machines the profile holds |

### Tasks tab

A vibration model has one Trendz task, and every scan runs as an execution of it: the scheduled ones and those
you start by hand. The **Tasks** tab shows that task, so you can check when each scan ran, whether it finished,
and how long it took.

<Aside>
The tab stays disabled until the model has run its first task.
</Aside>

## Actions

The header of the model page carries the actions that work on the whole model: **Scan latest data**, and under
**More actions**, **Duplicate**, **Scan more data**, and **Monitoring**. Everything the Overview, Monitoring, and
Analyzer tabs show comes from stored scan results, so the way to fill a gap is always a scan over the period the
gap is in.

### Scan latest data

**Scan latest data** reads the samples that arrived since the last scan:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/vibration/interface-scan-latest.webp',
    alt: 'Scan latest data button highlighted in the model page header',
    caption: 'Scan latest data continues every machine from its own newest stored sample.',
  },
]} />

- Each machine resumes from its newest stored sample and is read up to now, so nothing is computed twice.
- It covers the machines that were scanned at least once. New machines are added with **Scan more data**.
- This is the same operation the schedule runs, started by hand.

### Scan more data

**More actions** → **Scan more data** reads a period you choose, rather than only the newest samples:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/vibration/interface-actions-scan-more.webp',
    alt: 'More actions menu open in the model page header with Scan more data highlighted',
    caption: '<b>Scan more data</b> is in the <b>More actions</b> menu.',
  },
  {
    src: '/src/assets/images/trendz/vibration/interface-scan-more.webp',
    alt: 'Scan more data dialog with the period chips All history, Last 180 days, Last 90 days, and Last 30 days, a date picker, and the scope tabs',
    caption: 'Pick the period to scan.',
  },
  {
    src: '/src/assets/images/trendz/vibration/interface-scan-more-scope.webp',
    alt: 'Scope tabs of the Scan more data dialog: All in profile, Scanned items, and Specific',
    caption: 'Scope decides which machines the period is read for.',
  },
]} />

- Pick the period from the chips, **All history**, **Last 180 days**, **Last 90 days**, or **Last 30 days**, or
  open the date picker for a custom range.
- **Scope** decides which machines: **All in profile** also pulls in machines the model has not scanned yet,
  **Scanned items** covers the ones it already holds, and **Specific** covers the ones you list.
- The run restates the window: samples already stored inside it are overwritten, and results the rescan did not
  rewrite are dropped. Use it to fill history, to redo a period after fixing the data, or to add a machine.

### Duplicate

**More actions** → **Duplicate** creates a copy of the model and opens it in a new browser tab:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/vibration/interface-actions-duplicate.webp',
    alt: 'More actions menu open in the model page header with Duplicate highlighted',
    caption: '<b>Duplicate</b> copies the model into a new one.',
  },
]} />

- The copy carries the whole configuration, including bearings, machine details, and the envelope band, and the
  alarm rules. Edits made on the Properties tab and not yet saved are carried over too.
- Scheduled scanning, saving metrics as telemetry, and raising alarms are switched off on the copy, so the two
  models do not write the same keys. Turn them on in the copy's **Monitoring** settings when you need them.
- Scanned samples, spectra, and raised alarms are not copied: the copy starts its own scan.
- Use it to try a different configuration, such as another shaft speed or envelope band, without touching the
  model that is running.
