A trained prediction model is a snapshot. Monitoring keeps it current: Trendz refreshes the forecasts on a schedule,
writes them to ThingsBoard as telemetry, and raises alarms from event rules and targets.

## What continuous monitoring does

Every periodic refresh runs the same steps for each item of the model. Four switches decide which steps run:

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/monitoring-refresh.svg',
    alt: 'One periodic refresh across ThingsBoard and Trendz: the newest readings are read, the model is refitted when Scheduled retrain is on, the next values are predicted, predictions are saved to ThingsBoard as telemetry, rules and targets are checked, alarms are raised or cleared in ThingsBoard, and the Result tab shows the outcome; switches for periodic refresh, scheduled retrain, save telemetry, and alarm creation sit beside the steps they control',
    caption: 'One periodic refresh. Each switch turns on the step beside it.',
  },
]} />

| Switch | What the model does with each refresh |
|--------|----------------------------------------|
| **Periodic refresh** | Runs the refresh itself, every hour, day, or whatever period you set |
| **Scheduled retrain** | Refits the model on the latest data before it predicts |
| **Save telemetry** | Writes the forecast, event countdowns, and target progress to ThingsBoard |
| **Alarm creation** | Lets event rules and targets raise ThingsBoard alarms |

## Set up continuous monitoring

### Step 1. Open the monitoring settings

Click **Monitoring** in the page header (1), or **Configure** on the Continuous monitoring card (2). Both open the
same dialog with the four switches.

### Step 2. Turn on Periodic refresh

Switch **Periodic refresh** on and set how often it runs and for which items.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/monitoring-s2-refresh.webp',
    alt: 'Continuous monitoring configuration with the Periodic refresh card highlighted: every 1 hour, align off, scope All trained items',
    caption: 'Periodic refresh every hour for all trained items.',
  },
]} />

| Field | Description |
|-------|-------------|
| **Frequency** | How often the refresh runs: a count and a unit, **Minute**, **Hour**, **Day**, or **Week** |
| **Align to time unit start** | Starts each window on a whole unit: a 6-hour refresh at 00:00, 06:00, 12:00, and 18:00 |
| **Scope** | **All profile items** covers every item of the profile, **All trained items** only the trained ones, **Specific** the items you pick |

<Aside type="tip">
With **All profile items**, new devices that appear in the profile in ThingsBoard are discovered and trained
automatically, and the model starts refreshing them too.
</Aside>

A refresh that finds no new data for an item skips it.

### Step 3. Turn on Scheduled retrain

Switch **Scheduled retrain** on. Each refresh then first learns from the newest readings, and only then predicts.

<Aside type="caution" title="Strongly recommended">
Keep **Scheduled retrain** on for every model you rely on. Without it, the model stays exactly as it was trained:
it keeps predicting from the patterns it learned on day one, even after the device starts behaving differently.
</Aside>

### Step 4. Turn on Save telemetry

Switch **Save telemetry** on and enter a **Telemetry key**. Trendz writes the forecast to each device in
ThingsBoard under that key with an `_EPD_` prefix, and updates it at every refresh. You can then show it on
dashboards or use it in rule chains.

This switch is also the master switch for the telemetry of event rules and targets. To learn what those write,
see <DocLink product={props.product} path="prediction/intents/time-to-threshold">Time to Threshold</DocLink> and
<DocLink product={props.product} path="prediction/intents/hit-target">Hit Target</DocLink>.

### Step 5. Turn on Alarm creation

Switch **Alarm creation** on to let the model raise alarms. It is the master switch for every event rule and
target of the model: with it off, no alarm is raised, whatever the rules and targets say.

  {
    src: '/src/assets/images/trendz/prediction/monitoring-s5-alarms.webp',

    caption: 'Alarm creation on the model.',
  },
]} />

### Step 6. Save

Click **Save changes**. The header badge turns to **Enabled**, and the Continuous monitoring card shows the new
settings.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/monitoring-s6-card.webp',

    caption: 'The card after saving.',
  },
]} />

| Card cell | Shows |
|-----------|-------|
| **Periodic refresh** | **Disabled**, or **Every N units** |
| **Save telemetry** | **Enabled** or **Disabled** |
| **Alarm creation** | **Enabled** or **Disabled** |
| **Scheduled retrain** | **Configured** or **Not configured** |

<Aside type="caution">
Whatever a rule or target says, the model's **Alarm creation** switch from Step 5 must be on as well. A rule or
target with its own alarm switch on raises nothing while the model's switch is off. Trendz offers
**Open monitoring settings** when it notices the mismatch.
</Aside>

### Alarm lifecycle

ThingsBoard keeps one active alarm per item and alarm type:

- **Raised** when a rule or target reaches one of its severities.
- **Updated in place** when the severity changes.
- **Cleared** when no severity is reached any more.
- **Stays cleared** after an operator clears it, unless the severity gets worse.

Alarms are cleared, never deleted, so ThingsBoard keeps their history. From there they are normal ThingsBoard
alarms: show them in dashboards, or forward them by email, SMS, or to a ticketing system with a rule chain.
